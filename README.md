# 步道乐跑

面向步道乐跑的非官方 Windows + MuMu 模拟器定位与步数测试工具，提供自动联动、跑道轨迹模拟、中文安装教程和免 Python 的 Windows 下载包。基于 [EdmundMad0309/budao-lepao-runner](https://github.com/EdmundMad0309/budao-lepao-runner) 修改，按 MIT 许可证开源。

**下载即用版本：** [最新版发行包](https://github.com/a28638296-hub/budao-lepao-assistant/releases/latest) → 展开 **Assets** → 下载 `LePaoRunner-v2.1.0-windows-x64.zip`。普通用户不需要安装 Python。GitHub 的绿色 **Code → Download ZIP** 下载的是源码，不是可执行程序。

> 生成的是模拟运动数据，并不代表真实跑步。用于获得授权的开发、演示与定位测试；请勿提交虚假考勤或成绩。安装包不包含第三方 App，不代替本人登录，也不保证记录被服务端认定有效。

## 安装与首次使用

### 1. 准备环境

1. 使用 Windows 10/11 64 位电脑。
2. 从 [MuMu 官网](https://mumu.163.com/) 安装模拟器，确认开启 CPU 虚拟化。
3. 在 MuMu 多开器中创建并启动 **Android 12** 实例。已测试的配置是 Android 12、DirectX 渲染、ROOT 关闭。
4. 从官方渠道安装步道乐跑，使用本人账号完成登录。本版自动页面识别适配 **4.2.6**；其他版本的按钮和页面结构可能不同。本仓库不分发 APK，也不提供第三方破解包。
5. 在 Android 设置中开启“位置”，授予 App 精确位置权限；需要后台记录时允许相应后台权限并取消电池限制。进入乐跑首页，先结束此前未完成的记录。

### 2. 下载助手

1. 打开上面的最新版发行页，下载 Windows ZIP 和 `SHA256SUMS.txt`。
2. 将 ZIP **完整解压**到可写目录，如 `D:\Apps\LePaoRunner`；不要直接在压缩包里双击程序。
3. 可在 PowerShell 执行 `Get-FileHash .\LePaoRunner-v2.1.0-windows-x64.zip -Algorithm SHA256`，与发行页校验文件核对。
4. 双击 `LePaoRunner.exe`。EXE 未购买代码签名证书，Windows 可能提示未知发布者；先核对下载来源和校验值，不要关闭杀毒软件。

### 3. 首次设置模拟器

1. 选择 MuMu **安装根目录**，其中应存在 `nx_main\MuMuManager.exe`。不是模拟器虚拟机的数据目录。
2. 点“查询实例编号”，查看名称与编号；填入正在运行且已登录 App 的实例编号。主实例通常为 `0`，多开实例不一定是 `1`。
3. 点“保存并打开助手”。程序根据所选实例读取网关端口与 ADB 地址，不要求使用作者的安装路径。
4. 要更换目录或实例：在 EXE 所在目录运行 ` .\LePaoRunner.exe --setup`，重新设置。

### 4. 核对跑道坐标（必须做）

**默认六点只是南宁学院田径场的公开坐标示例，不会自动定位你的学校。** 自动联动每次启动默认关闭，先检查坐标再启用。

以地图北朝上为准，将六点依次填为：

| 点 | 位置 |
|---|---|
| 1 | 北端弯道顶点 |
| 2 | 东侧直道北端与弯道相接处 |
| 3 | 东侧直道南端与弯道相接处 |
| 4 | 南端弯道顶点 |
| 5 | 西侧直道南端与弯道相接处 |
| 6 | 西侧直道北端与弯道相接处 |

选择与坐标来源相符的坐标系：高德/腾讯用 GCJ-02，百度用 BD-09，GPS 用 WGS-84。每行先纬度、后经度；中国经度通常大于 90，填反会报错。修改六点后，路线和边界都会重新计算。

程序用两条直道、两端半圆拟合标准田径跑道，并沿参考线内侧约 0.1～1.85 米分圈移线。六点应标在跑道合适的参考线上，保证内移后仍在跑道上；不能把草坪边缘直接当参考线。非标准形状、地图偏移或错误坐标无法由程序自动修正。先在地图上核对位置，勿将示例当作测绘结果。

### 5. 自动联动

1. 填起始配速，单位是 **分钟/公里**：`7.5` 表示 7 分 30 秒/公里；范围 6～9。填写圈数，步频可保持 `0`（自动）；模拟步数受模拟器接口限制，并非真人生理步频模型。
2. 保持乐跑在**首页待跑**，勾选助手的“启用自动联动（已核对六点跑道坐标）”。
3. 等状态显示“随机起点已就绪、GPS 已开启”。此时已经完成随机起点准备；首页没有 GPS 请求时，助手会等 App 申请定位后再确认。
4. 在乐跑点“开始乐跑”，完成 App 自身要求的提示或倒计时，保持跑步页面。助手识别到正式记录并确认 GPS 接近起点后自动移动，无须另点助手开始按钮。
5. 方向固定为**逆时针**（地图北朝上时，东侧直道向北），配速在 6～9 分钟/公里内随机平滑变化，目标过渡间隔 60～100 秒。每圈缓慢横向错开，保留内外边界检查。
6. 可在模拟器地图中观察过程。乐跑暂停时助手跟随暂停，继续后恢复；无法确认页面状态超过 15 秒时暂停移动。切换到其他 App、遮挡界面或息屏可能影响检测。
7. 达到设定圈数后，助手停止定位与步数；**仍需本人在乐跑结束记录**。助手“停止”按钮或取消自动联动也可停止助手，但不会代替 App 提交、删除或结束记录。
8. 返回首页后自动准备下一次起点。同一条记录不会反复自动启动。若助手是在记录中途才打开，先结束记录再回首页准备，不会直接随机跳点。

## 数据存放

本地设置在 `%APPDATA%\LePaoRunnerCommunity\`：`launcher.json` 保存模拟器选择，`config.json` 保存界面设置，`route_history.json` 保存生成路线历史。EXE 目录可能同步生成 `config.json`。不要把这些文件提交到公开仓库。

程序不需要 GitHub 密码或 App 账号密码。登录与授权由本人在 App 中完成。它不会上传路线历史到本项目；模拟器中的 App 自身网络行为另当别论。

## 源码与构建

需要含 Tkinter 的 Python 3.13～3.15；本次构建环境为 Python 3.15.2 + PyInstaller 6.22.3。运行程序只使用标准库。

```powershell
git clone https://github.com/a28638296-hub/budao-lepao-assistant.git
cd budao-lepao-assistant
python launch.py
```

离线测试不会创建真实运动记录：

```powershell
python -m unittest discover -s tests -v
```

重新构建 Windows EXE：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
.\build_exe.ps1 -Python .\.venv\Scripts\python.exe
```

产物为 `dist\LePaoRunner.exe`。只读启动检查：` .\dist\LePaoRunner.exe --smoke-test smoke.json`；检查文件中应有 `"ok": true`。不要同时运行多个正式助手控制同一实例。

## 已知限制与验证范围

- 验证包含方向几何、环带/连线边界、随机配速、分圈间距、GPS 检查、自动联动状态机，以及从 4.2.6 现场采集的按钮结构回归。
- 页面检测修复已由现场结构确认；并未完成所有电脑、App 版本上的真实记录端到端验证，不承诺通用兼容或成绩有效。
- 地图线条有宽度，GPS 与坐标转换有误差；生成点分开，不代表地图显示绝不重叠。圈数越多，有限宽度内每圈间距越小。
- 草坪保护依赖你填写的六点与几何模型，无法识别现实道路、围栏或学校实际边界。
- APK、微信、MuMu 均需另行安装，不随发行包分发。账号登录问题需由对应服务解决。
