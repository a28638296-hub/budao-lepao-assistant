# Android 12：从下载到首次检查的详细安装教程

> App 升级到 4.3.3 后打不开时，先看 [Android 12 保留数据回退说明](APP_UPDATE_RECOVERY.md)。不要直接卸载或清除数据。

> v2.3.0 Windows ZIP 已包含本次全部修复，无需 Python。完整解压、完成首次配置后，从助手打开并在乐跑开始记录即可自动联动。

适用版本：v2.3.0。本教程只介绍 MuMu Android 12 的安装与配置。助手运行在 Windows 电脑上，通过 MuMu 控制所选 Android 实例。不能把 Windows EXE 安装到安卓手机中。

## 1. 先分清需要安装的程序

| 程序 | 安装在哪里 | 用途 |
|---|---|---|
| MuMu 模拟器 | Windows 电脑 | 提供 Android 环境 |
| 步道乐跑 | MuMu 的目标实例内 | 打开页面、本人登录 |
| 微信（选择微信登录时） | 同一个 MuMu 实例内 | 完成本人账号授权 |
| LePaoRunner.exe | Windows 电脑 | 配置、连接和测试 |

每个多开实例相互独立：请把步道乐跑和微信都安装在选定的 Android 12 实例内；另一个实例的安装和登录状态不会自动传过来。电脑微信不能代替实例内的 Android 微信。

准备 Windows 10/11 64 位电脑。从 [MuMu 官网](https://mumu.163.com/)取得模拟器。若模拟器提示虚拟化未开启，先按其官方说明处理，确认 Android 桌面可以正常打开，再安装助手。

## 2. 创建并启动 Android 12 实例

1. 打开 MuMu 多开器，选择已有的 **Android 12** 实例；如果没有，就创建一个 Android 12 实例。只启动该实例，不需要打开其他系统版本。
2. 启动它，等待进入 Android 桌面。首次启动尚未完成时不要查询连接。
3. 记下实例名称和系统版本，后面在助手中核对编号。编号不是 Android 版本号，也不一定等于多开列表的行号。
4. 在实例的系统设置中确认 Android 版本为 **12**；后面安装 App、微信和连接助手都使用这个实例。

**兼容性说明：** 助手支持 Android 12 及更高版本的相关接口，不设置 Android 版本上限；本文只提供 Android 12 的安装步骤。更高版本不代表全部实测：Android 15 已检查设备接口，完整登录与记录流程未验证；其他版本的验证范围见 [兼容性表](../README.md#已知限制与验证范围)。

## 3. 安装 App 并完成微信登录

1. 从 App 官方渠道或可信应用商店取得步道乐跑，在目标实例内安装。使用 MuMu 的 APK 安装入口时，确认接收安装的是目标实例。
2. 单独打开步道乐跑，确认能停留在首页或登录页。助手的页面识别针对 **4.2.6**；不要把其他版本能够启动理解为自动联动已经适配。
3. 如果选择微信登录，先在**同一实例**安装 Android 微信，再打开微信，由本人完成登录和必要的验证。
4. 返回步道乐跑，点击“点击登录”或登录入口。本人阅读并决定是否同意页面上的用户协议与隐私政策，再点击“微信登录”。
5. 在微信中由本人确认授权。成功后回到步道乐跑，检查是否已退出登录页并显示账号首页。
6. 若 App 要求身份认证或其他信息，由本人按 App 提示处理。助手不提供账号，也不会代填密码、验证码或身份信息。

仓库与下载包不包含步道乐跑、微信或 MuMu 安装包。只需在所选 Android 12 实例里完成上述步骤，无需额外安装更高系统版本。

## 4. 检查位置权限

1. 在 Android 系统设置中打开“位置”总开关。
2. 打开步道乐跑的应用信息 → 权限 → 位置，允许使用所需的位置权限；有“精确位置”选项时开启。
3. 如果 App 提示还需要运动相关权限，按实际需求处理。后台位置和电池限制设置以系统和 App 的实际提示为准。
4. 返回 App 查看地图。总开关开启只说明允许定位，不能证明 App 已收到新的 GPS 点。

先确认 App 本身可启动、登录和获取权限，再排查助手；不要一边切换账号或实例，一边启动联动。

### 首次安装必须完成：GPS 诊断组件

在同一 Android 12 实例中，从 [GPSTest 官方 v3.10.6 发行页](https://github.com/barbeau/gpstest/releases/tag/v3.10.6) 获取 `osmdroidRelease-v3.10.6.apk` 并安装。打开一次，授予使用期间的精确位置权限。启动器需要包名 `com.android.gpstest.osmdroid`，不要选其他构建。该组件不随 ZIP 分发。详见文末定位检查步骤。

## 5. 下载并解压 Windows 助手

1. 打开 [最新版发行页](https://github.com/a28638296-hub/budao-lepao-assistant/releases/latest)。
2. 展开 **Assets**，下载 `LePaoRunner-v2.3.0-windows-x64.zip` 和 `SHA256SUMS.txt`。
3. 不要选择 `Source code (zip)`；绿色 Code 按钮下的 Download ZIP 也是源码。
4. 在下载目录打开 PowerShell，执行：

   ```powershell
   Get-FileHash .\LePaoRunner-v2.3.0-windows-x64.zip -Algorithm SHA256
   ```

5. 将输出 Hash 与校验文件对应文件名那一行比较；字母大小写不影响比较。若不一致，停止使用并重新下载。
6. 右键 ZIP → 全部解压，放到自己有写权限的目录，例如 `D:\Apps\LePaoRunner`。打开解压后的文件夹，双击 `LePaoRunner.exe`。
7. 保留包内的 `portable-mode.txt`，它让配置、实例选择、日志和历史统一保存在 EXE 旁的 `user-data`。不要删除这个文件或只移动 EXE。建议右键 EXE → 显示更多选项 → 发送到 → 桌面快捷方式；始终使用这一个入口。
8. 普通用户无需 Python。EXE 未签名，遇到系统拦截先核对来源、校验值和安全中心记录，不要关闭安全软件。

## 6. 连接正确的 MuMu 实例

1. 保持目标实例运行，在首次设置窗口点击“浏览”。
2. 选择 MuMu **安装根目录**，例如 `C:\Program Files\Netease\MuMu`。这只是示例，以本机实际路径为准。
3. 检查该目录下面是否存在 `nx_main\MuMuManager.exe`。不要选择 `nx_main` 本身、下载目录或虚拟机数据目录。
4. 点击“查询实例编号”，根据名称和 Android 版本找到刚才启动的 **Android 12** 实例，将其编号填入输入框。
5. 点击“保存并打开助手”，然后点击“自检”。查看日志中的 Android/API、CPU 架构、App 版本和位置开关是否与目标实例一致。
6. 自检是只读检查，不移动坐标、不发送步数。自检成功也不等于登录和完整记录流程验证成功。

如果误选了其他实例，先关闭助手，使用以下命令重新选择 Android 12 实例，在 EXE 文件夹内打开 PowerShell：

```powershell
.\LePaoRunner.exe --setup
```

如果当前目录不是程序所在目录，可以使用完整路径：

```powershell
& 'D:\Apps\LePaoRunner\LePaoRunner.exe' --setup
```

路径换成本机路径。不要同时打开多个助手控制同一实例。

## 7. 首次配置与观察

默认坐标仅为公开示例。填写前阅读 [README 的六点坐标说明](../README.md#4-核对跑道坐标必须做)，核对坐标系、纬经度顺序和六个点的位置。界面顶部的方向文字描述行进方向；输入点编号请按 README 表格和 `track.py` 的六点定义填写，两者不要混淆。

点击“保存默认”保存参数。首次使用自动联动默认关闭；核对坐标后勾选并点击“保存默认”，后续启动会恢复此选择。具体状态顺序、暂停与停止行为见 [自动联动说明](../README.md#5-自动联动)。仅在获得授权的测试场景中使用模拟数据。

首次观察保持模拟器窗口可见，不勾选“后台运行：把模拟器窗口移到屏幕外”。已隐藏时可点击“显示模拟器（看进度）”。同时观察 App 页面和助手运行日志；助手状态与 App 自身的记录状态是两回事。

停止助手不会替 App 结束、提交或删除记录。完成测试后在 App 中本人处理当前状态。请勿提交虚假考勤或成绩。

## 8. 更新版本与保留设置

1. 在 App 处理尚未结束的记录，关闭旧助手；不要同时运行新旧两版。
2. v2.3.0 默认固定目录模式：备份旧程序旁整个 `user-data` 文件夹；不要公开其中的配置和日志。
3. 将新 ZIP 完整解压到新的可写目录。将备份的 `user-data` 复制到新 EXE 旁，保留随包的 `portable-mode.txt`。
4. 从 v2.2.x 升级：旧设置通常在 `%APPDATA%\LePaoRunnerCommunity`。关闭旧版后，可把其中的 `config.json`、`launcher.json` 和需要保留的 `route_history.json` 复制到新目录的 `user-data`；若不确定旧配置是否正确，直接在新版重新选择实例并填写六点。
5. 新版不自动开启未确认的联动。核对坐标、勾选“启用自动联动”、点“保存默认”；关闭再打开，确认勾选仍在且日志载入的是同一 `user-data/config.json`。
6. 删除旧桌面快捷方式并给新版 EXE 建立新的快捷方式；保留旧程序文件夹作为回退即可。
7. 更新助手不会升级 MuMu、步道乐跑、微信，也不会复制账号登录状态。


## 9. 仍然失败时提供哪些信息

查看 [故障排查](TROUBLESHOOTING.md)。报告 Windows、MuMu、Android/API、助手和 App 版本，以及失败发生在哪一步、预期现象、实际现象和脱敏日志。截图应遮挡姓名、账号、学校身份信息、登录二维码与验证码。

不要发送密码，也不要上传整个配置目录。登录问题由对应服务处理；助手问题可以提交到本仓库 Issues。


## 启动定位组件与重新打开验证

以下步骤适用于 v2.3.0 下载包；v2.2.0 及更早包没有完整的启动定位检查。

1. 只启动准备使用的 Android 12 实例。
2. 打开 [GPSTest 官方发行页](https://github.com/barbeau/gpstest/releases/tag/v3.10.6)，下载 `osmdroidRelease-v3.10.6.apk`，拖入这个模拟器安装。不要选择另一个包名的构建；启动器调用 `com.android.gpstest.osmdroid`。本项目不捆绑该 APK。
3. 在模拟器内打开 GPSTest，允许精确位置访问和使用期间定位，确保 Android 系统定位开关开启。若未弹出授权框，到 Android 设置 → 应用 → GPSTest → 权限 → 位置中授权。
4. 双击已解压的 `LePaoRunner.exe` 打开助手，选择同一个实例。首次先核对六点和坐标系，点击“保存默认”。默认例子不等于你的学校，也不替代现场测绘。
5. 确认没有正在记录的跑步，关闭助手后重新打开。先出现 GPSTest 是启动定位检查的一部分；确认位置后会自动切回乐跑，无须操作 GPSTest。
6. 进入乐跑待跑地图，确认定位标记落在自己的跑道，再开始测试。若提示 GPS 超时，检查步骤 3，不要把旧地图中心当成当前位置。
7. 模拟器重启后也通过助手打开。只点 MuMu 或单独打开乐跑会绕过启动前校正；助手启动后保持运行。

启动检查会先下发补偿，再连续三次确认实际 GPS 在内圈且距目标小于 0.35 米，才切回乐跑。短暂显示 GPSTest 属于正常流程；不要在检查期间手动切换应用。第一次尚未保存六点时需先完成配置，再重开助手验证。

## 10. 每次使用与成功标准

1. 双击桌面的新版助手快捷方式。等待“正在启动”窗口结束；只会启动你选定的实例。
2. 保持助手运行。在乐跑首页点击“开始乐跑”，完成 App 自身的提示和倒计时。非学校规定时段可能只允许自由跑，这由 App 决定。
3. 无需点击助手的准备或开始按钮。观察助手日志出现“检测到乐跑记录中，已自动开始运行”，并确认 App 的距离增加、绿色轨迹延伸；仅计时增加不算成功。
4. 暂停时在 App 操作；助手识别后暂停移动。结束后回首页，为下次记录重新准备。不要在旧记录暂停时关闭助手后，把“继续”当作新记录开始。
5. 完成设定圈数仅停止助手移动，仍须本人处理 App 的记录。若出现错误，保留窗口并查看 `user-data/assistant.log`，按排错指南检查。

默认地图坐标只是公开示例。轨迹与 GPS 检查基于填写的六点，不具备测绘精度，也不保证所有设备与后续 App 版本都兼容。
