# 从下载到首次检查：详细安装教程

适用发行版：v2.2.1。助手运行在 Windows 电脑上，通过 MuMu 控制所选 Android 实例。不能把 Windows EXE 安装到安卓手机中。

## 1. 先分清需要安装的程序

| 程序 | 安装在哪里 | 用途 |
|---|---|---|
| MuMu 模拟器 | Windows 电脑 | 提供 Android 环境 |
| 步道乐跑 | MuMu 的目标实例内 | 打开页面、本人登录 |
| 微信（选择微信登录时） | 同一个 MuMu 实例内 | 完成本人账号授权 |
| LePaoRunner.exe | Windows 电脑 | 配置、连接和测试 |

每个多开实例相互独立：Android 12 中安装了微信，不代表 Android 15 中也有微信；一个实例的登录状态也不会自动传到另一个实例。电脑微信不能代替实例内的 Android 微信。

准备 Windows 10/11 64 位电脑。从 [MuMu 官网](https://mumu.163.com/)取得模拟器。若模拟器提示虚拟化未开启，先按其官方说明处理，确认 Android 桌面可以正常打开，再安装助手。

## 2. 创建并启动目标实例

1. 打开 MuMu 多开器，选择已有的 Android 12 或以上实例，或创建新的实例。
2. 启动它，等待进入 Android 桌面。首次启动尚未完成时不要查询连接。
3. 记下实例名称和系统版本，后面在助手中核对编号。编号不是 Android 版本号，也不一定等于多开列表的行号。
4. 在实例的系统设置中查看 Android 版本；设置菜单名称可能随镜像不同而变化。

**本项目不保证所有 Android 版本都已实测。** Android 12 与 15 已检查连接、GPS 开关和界面读取；13、14、16 及更高版本尚无本地实机验证。

## 3. 安装 App 并完成微信登录

1. 从 App 官方渠道或可信应用商店取得步道乐跑，在目标实例内安装。使用 MuMu 的 APK 安装入口时，确认接收安装的是目标实例。
2. 单独打开步道乐跑，确认能停留在首页或登录页。助手的页面识别针对 **4.2.6**；不要把其他版本能够启动理解为自动联动已经适配。
3. 如果选择微信登录，先在**同一实例**安装 Android 微信，再打开微信，由本人完成登录和必要的验证。
4. 返回步道乐跑，点击“点击登录”或登录入口。本人阅读并决定是否同意页面上的用户协议与隐私政策，再点击“微信登录”。
5. 在微信中由本人确认授权。成功后回到步道乐跑，检查是否已退出登录页并显示账号首页。
6. 若 App 要求身份认证或其他信息，由本人按 App 提示处理。助手不提供账号，也不会代填密码、验证码或身份信息。

**Android 15 当前进度：** 本地 App 4.2.6 能打开，微信 8.0.79 已安装并发出启动请求；微信登录、授权及登录后的完整流程仍待本人操作验证。这不是对微信所有功能或完整记录流程的兼容性承诺。仓库与下载包均不包含上述 APK。

## 4. 检查位置权限

1. 在 Android 系统设置中打开“位置”总开关。
2. 打开步道乐跑的应用信息 → 权限 → 位置，允许使用所需的位置权限；有“精确位置”选项时开启。
3. 如果 App 提示还需要运动相关权限，按实际需求处理。后台位置和电池限制设置以系统和 App 的实际提示为准。
4. 返回 App 查看地图。总开关开启只说明允许定位，不能证明 App 已收到新的 GPS 点。

先确认 App 本身可启动、登录和获取权限，再排查助手；不要一边切换账号或实例，一边启动联动。

## 5. 下载并解压 Windows 助手

1. 打开 [最新版发行页](https://github.com/a28638296-hub/budao-lepao-assistant/releases/latest)。
2. 展开 **Assets**，下载 `LePaoRunner-v2.2.1-windows-x64.zip` 和 `SHA256SUMS.txt`。后续版本以发行页文件名为准。
3. 不要选择 `Source code (zip)`；绿色 Code 按钮下的 Download ZIP 也是源码。
4. 在下载目录打开 PowerShell，执行：

   ```powershell
   Get-FileHash .\LePaoRunner-v2.2.1-windows-x64.zip -Algorithm SHA256
   ```

5. 将输出 Hash 与校验文件对应文件名那一行比较；字母大小写不影响比较。若不一致，停止使用并重新下载。
6. 右键 ZIP → 全部解压，放到自己有写权限的目录，例如 `D:\Apps\LePaoRunner`。打开解压后的文件夹，双击 `LePaoRunner.exe`。
7. 普通用户无需 Python。EXE 未签名，遇到系统拦截先核对来源、校验值和安全中心记录，不要关闭安全软件。

## 6. 连接正确的 MuMu 实例

1. 保持目标实例运行，在首次设置窗口点击“浏览”。
2. 选择 MuMu **安装根目录**，例如 `C:\Program Files\Netease\MuMu`。这只是示例，以本机实际路径为准。
3. 检查该目录下面是否存在 `nx_main\MuMuManager.exe`。不要选择 `nx_main` 本身、下载目录或虚拟机数据目录。
4. 点击“查询实例编号”，根据名称和 Android 版本找到刚才启动的实例，将其编号填入输入框。
5. 点击“保存并打开助手”，然后点击“自检”。查看日志中的 Android/API、CPU 架构、App 版本和位置开关是否与目标实例一致。
6. 自检是只读检查，不移动坐标、不发送步数。自检成功也不等于登录和完整记录流程验证成功。

要重新选择实例，先关闭助手，在 EXE 文件夹内打开 PowerShell：

```powershell
.\LePaoRunner.exe --setup
```

如果当前目录不是程序所在目录，可以使用完整路径：

```powershell
& 'D:\Apps\LePaoRunner\LePaoRunner.exe' --setup
```

路径换成本机路径。不要同时打开多个助手控制同一实例。

## 7. 首次配置与观察

默认坐标仅为公开示例。填写前阅读 [README 的六点坐标说明](../README.md#4-核对跑道坐标必须做)，核对坐标系、纬经度顺序和六个点的位置。界面顶部的方向文字描述行进方向；输入点编号请按 README 表格和 `track.py` 的六点定义填写，两者不要混淆。

点击“保存默认”保存参数。首次使用自动联动默认关闭；核对坐标后勾选并点击“保存默认”，后续启动会恢复此选择。具体状态顺序、暂停与停止行为见 [自动联动说明](../README.md#5-自动联动)。仅在获得授权的测试场景中使用模拟数据。

首次观察保持模拟器窗口可见，不勾选“后台运行：把模拟器窗口移到屏幕外”。已隐藏时可点击“显示模拟器（看进度）”。同时观察 App 页面和助手运行日志；助手状态与 App 自身的记录状态是两回事。

停止助手不会替 App 结束、提交或删除记录。完成测试后在 App 中本人处理当前状态。请勿提交虚假考勤或成绩。

## 8. 更新版本与保留设置

1. 停止助手任务，处理好 App 中尚未结束的状态，关闭旧助手。
2. 备份 `%APPDATA%\LePaoRunnerCommunity\`；若旧 EXE 旁有 `config.json`，也单独备份。文件可能含个人位置，勿上传公开仓库。
3. 将新版本 ZIP 解压到新的文件夹，保留旧文件夹便于回退。
4. 新版通常会读取同一用户配置目录。EXE 同目录的 `config.json` 具有覆盖作用，不要误用别人提供的配置。
5. 打开新版，先自检，核对实例和坐标，再进行测试。更新助手不会自动升级 MuMu、步道乐跑或微信，也不会迁移它们的登录状态。

## 9. 仍然失败时提供哪些信息

查看 [故障排查](TROUBLESHOOTING.md)。报告 Windows、MuMu、Android/API、助手和 App 版本，以及失败发生在哪一步、预期现象、实际现象和脱敏日志。截图应遮挡姓名、账号、学校身份信息、登录二维码与验证码。

不要发送密码，也不要上传整个配置目录。登录问题由对应服务处理；助手问题可以提交到本仓库 Issues。
