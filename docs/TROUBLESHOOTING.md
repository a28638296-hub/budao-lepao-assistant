# 安装与故障排查

> App 升级到 4.3.3 后打不开时，先看 [Android 12 保留数据回退说明](APP_UPDATE_RECOVERY.md)。不要直接卸载或清除数据。

尚未完成安装时，先按 [详细安装教程](INSTALL.md) 核对每一步。

## 微信登录无反应 / 提示未安装微信

确认 Android 微信安装在步道乐跑所在的同一个 MuMu 实例中。电脑微信和其他实例中的微信不能替代它。先单独打开微信，由本人完成登录，再返回乐跑发起授权；协议勾选和授权由本人处理。新建实例不会继承其他实例的账号状态；按教程统一使用选定的 Android 12 实例。

若微信或乐跑在授权时退出，记录具体发生在哪个页面和两个 App 的版本，不要反复点击授权或清除应用数据。安装成功不等于登录成功，请在 Android 12 实例中本人完成授权。

## 双击 EXE 没有反应

完整解压 ZIP，检查系统是否为 64 位 Windows 10/11，并查看 Windows 安全中心的拦截记录。核对发行包 SHA256；不要从不明网盘取得修改版，也不要关闭安全软件。第一次解压单文件运行环境可能需要数秒。

## 找不到 MuMu / ADB 连接失败

运行 `LePaoRunner.exe --setup`，选择包含 `nx_main\MuMuManager.exe` 的安装目录。点“查询实例编号”，查看系统版本并确认目标实例已经启动。助手和 App 必须针对同一个实例。v2.2.0 会在断连时重新查询该实例端口并连接，不会重启整个 ADB 服务。仍失败时点“自检”查看具体错误。

## 点开始后不移动

重新打开助手时，最新源码会先下发并验证定位补偿，连续三次确认 GPS 在内圈、距启动目标不足 0.35 米，再打开乐跑。仅计算补偿但没有验证实际位置的旧启动流程可能留下偏差。启动器也会传递已确认无运行记录的状态，避免快速点击首页开始时漏掉联动。Windows 单实例锁已修正，重复启动不会再运行第二个助手。

最新源码修复了快速点击开始时的联动时序：若起点已下发但校正尚未完成，会保留候选路线并继续核对实际 GPS；若尚未准备路线，但助手刚观察到待跑页面，会先确认当前 GPS 在内圈，再从当前位置衔接。两种情况都不会在记录中重新下发随机起点，也不会跳过位置校验。v2.3.0 下载包已包含此修复。

按顺序核对：

1. 助手已勾选自动联动，并在 App 开始前显示随机起点已就绪。
2. 已通过 App 自身的权限提示、确认和倒计时，进入正式计时页面。
3. Android 位置开关开启，App 精确位置权限允许。助手等待的实际 GPS 点必须距准备起点不超过 5 米且落在内圈。
4. 保持 App 跑步页在前台，勿停留在登录页、广告、设置或其他 App。
5. 使用适配的 4.2.6。该版暂停按钮自行绘制文字，普通无障碍读取可能为空，社区版用原生控件可见性识别；新版本页面结构变化需要更新代码。
6. 如果助手在记录开始后才启动，结束该条记录、返回首页重新准备。不要在记录中手动改定位。

## 位置跑到其他学校 / 草坪 / 跑道外

v2.2.1 会在首页持续复查已准备起点。升级后核对六点，勾选自动联动并点“保存默认”，以后从助手入口打开并保持助手运行。只修改 MuMu 的默认定位字段不能保证它不会恢复历史位置；不要把历史坐标直接当成 Android 的实际 GPS。

实际 GPS 必须落在配置内圈且距起点不超过 5 米；运行中读到越界位置会停止助手。若提示未确认，请回首页等待恢复，不要在已有记录中手动跳点。需要定位证据时，可以使用 GPS 查看工具读取新位置；首页不申请 GPS 时系统可能只有缓存或没有位置。

默认坐标是南宁学院示例，必须替换成你的跑道。核对纬经度顺序、坐标系和六点顺序。六点不是随便选的六个角，而是跑道两端顶点及四个直道相接点。

参考线会向内移约 0.7～1.3 米，所以要给草坪边缘留余量。边界模型近似，不能当作现场测绘。配准失败时先停止测试，重新校准后从首页准备。

## App 闪退

助手面向 MuMu Android 12 及以上，已检查 Android 12 和 15 的设备接口；App 本身使用的原生库、CPU 转译或渲染兼容性仍由 App 与模拟器决定。可先尝试 DirectX 渲染、关闭 ROOT，并从官方渠道取得适配系统的 App。不要通过修改 APK 版本声明掩盖闪退。更改实例前先保存需要的数据。

点“自检”记录 Android/API、CPU 架构与 App 版本，报告闪退发生在启动、登录还是记录阶段。若 App 根本无法独立启动，助手不能替代其原生库适配。

## Android 15 界面读取异常

部分镜像中的 `uiautomator dump` 在成功写出 XML 后仍返回非零退出码。v2.2.0 仅在返回内容明确确认写入当前目标文件时继续解析；真实错误、错误路径或无效 XML 仍会被拒绝。未登录页面会保持等待，不会误触发跑步。

## 轨迹看起来重叠 / 配速和助手日志不同

最新源码将路线限制在参考线内侧约 0.7～1.3 米，为坐标转换残差与 GPS 小数取整留出空间，避免逐圈向边缘偏移后才触发停止。内圈校验范围没有放宽；真实越界仍停止，日志会显示相对参考线的偏移量。每圈依然错开，但屏幕上的间距会比旧版更小。

2026-11-08 在 MuMu Android 12、App 4.2.6 自由跑模式完成一次 5 圈验证：助手累计 1.723 公里、12 分 28 秒、750 次位置下发，无下发失败；每 5 秒读取的 144 个 GPS 样本均在配置内圈内。日志采样的目标配速为 6′03″～8′30″/公里，App 最后显示 1.74 公里、平均 7′16″/公里。完成后暂停 App，未操作结束或提交。本次结果仅代表这一设备与配置，不能保证所有设备或以后每次运行都无误。

地图画线宽度与 App 的 GPS 平滑算法会改变显示效果；每圈坐标错开并不能保证屏幕线条分离。显示的平均配速也包含记录开始后等待 GPS 的时间，和当前目标配速不是同一个数值。

## 改完设置后不生效

如果从桌面和其他环境启动时读到了不同的 Roaming 配置，可使用固定目录模式（最新源码）：退出助手，在程序所在的可写目录中新建空文件 `portable-mode.txt`，再启动并核对六点、勾选自动联动、保存默认。此后配置、日志和路线历史统一写入程序旁的 `user-data` 文件夹；升级时保留这个文件夹。旧 Roaming 文件不会删除。该模式不会自动迁移旧账户配置，也不会自动开启联动；不要把 `user-data` 上传到 GitHub。

路线在准备时生成。改变坐标或圈数后，先回乐跑首页等待重新准备。正在运行的记录不会被瞬间改成另一条路线。查看日志确认当前实例及准备状态。

## 报告问题

v2.3.0 下载包默认将助手日志保存到程序旁 `user-data/assistant.log`（未启用固定目录模式的源码运行使用 `%APPDATA%\LePaoRunnerCommunity\assistant.log`）；运行停止时会显示错误原因。反馈“已经计时但地图不动”时，请附开始前后几行日志，并说明助手是在记录之前还是之后打开。

在 GitHub Issues 提供 Windows/MuMu/Android/App 版本、问题步骤及已去除个人信息的日志片段。不要上传密码、登录二维码、验证码、个人运动记录、完整配置目录或敏感截图。


## 打开后不移动：GPS 缓存与细小偏差

最新源码改为读取 Android 的 `gps provider` 当前值，避免将 `passive provider` 保存的旧位置当成当前 GPS。准备起点时连续读取三个稳定样本，校正模拟器转换造成的小偏差；补偿不超过 3 米，运行中仍执行原有内圈边界检查。校正只在待跑时进行，不移动已开始或暂停的记录。

从助手启动，进入乐跑待跑地图，等待助手确认起点就绪，再点地图底部“开始乐跑”。首页不一定请求 GPS，只有“已下发”或旧地图标记不能证明起点就绪。校正未通过时会说明原因，而不会把未验证的起点标成可运行。

如果首页“开始乐跑”长时间无响应或提示获取位置失败，检查模拟器网络。2026-11-08 本机发现 Android 的自动私人 DNS 查询大量超时，改为关闭该实例的私人 DNS 后恢复；只在存在同类诊断证据时调整，其他设备不必照改。可在 Android 设置搜索“私人 DNS”进行调整，并记录原值以便恢复。

本机 Android 12 短程验证：点击开始后自动移动约 70 米，App 显示 0.07 公里、31 秒、平均配速 7′37″/公里；采样点均通过配置内圈检查。随后按 App 的短距离不保存提示结束测试，未保存记录。此次验证不是完整圈数或所有设备兼容性验证。上述修复已包含在 v2.3.0 下载包中。
